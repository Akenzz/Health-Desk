02 — Learning Journey

Concepts Learned, Applied in HealthSync

A chronological map of every core Web Technologies concept covered in the course — and exactly how each was implemented inside the HealthSync platform.

Frontend Development

HTML · CSS · JavaScript

Semantic markup, responsive layouts with Flexbox & Grid, component-driven UI patterns, and accessible form handling.

Applied: Built HealthSync's patient dashboard, doctor portal, and medicine request UI with responsive grids and accessible forms.

Backend Development

Node.js · Express

Server-side runtime, request lifecycle, routing, controllers, services, and modular project structuring.

Applied: Express server powering HealthSync APIs — patient routes, doctor routes, health-record services, and the MedReach submission engine.

Database Design

MongoDB · Schemas

Document modeling, normalization vs. denormalization, schema validation, indexing strategies.

Applied: Designed 7+ collections including users, patients, records, medicines, requests, and notifications.

REST APIs

HTTP · JSON · Versioning

RESTful resource design, status codes, idempotency, query parameters, and consistent JSON contracts.

Applied: 25+ REST endpoints under /api/v1/* covering auth, patients, doctors, records, medicines, and pharmacy services.

Authentication

JWT · bcrypt

Stateless tokens, password hashing, refresh strategies, and protected route patterns.

Applied: JWT-based login for patients, doctors, and pharmacists with role claims and bcrypt-hashed passwords.

MVC Architecture

Separation of Concerns

Models for data, Views for presentation, Controllers for orchestration — keeping business logic clean.

Applied: HealthSync codebase split into /models, /views, /controllers for predictable maintenance.

Agile Methodology

Scrum · 4 Sprints

User stories, sprint planning, daily standups, retrospectives, and iterative delivery.

Applied: Delivered HealthSync across 4 focused sprints with a maintained backlog and demos at each sprint review.

Testing & Validation

Unit · Integration · UAT

Functional, security, validation and acceptance testing, with structured test cases and reports.

Applied: 40+ test cases written across authentication, data integrity, and end-to-end medicine request flows.

12 — Challenges & Solutions

Engineering Problems, Solved

A few of the hardest moments — and the engineering decisions that unblocked them.

Challenge

Sensitive data leaking through API responses

Mongoose returned full user documents — including password hashes — in early auth endpoints.

Solution

Schema projection + response DTOs

Added .select('-password'), a global response serializer, and a strict allow-list of fields per endpoint.

Challenge

Role-based access was scattered across controllers

Permission checks were duplicated and easy to forget on new routes.

Solution

Single RBAC middleware

Centralized requireRole('doctor') middleware applied at the route layer, enforcing access uniformly.

Challenge

Flaky notifications during medicine requests

Notifications occasionally fired twice or not at all under load.

Solution

Event-driven model + idempotency keys

Introduced an event bus with unique request IDs so handlers are safely retried.

Challenge

Form validation drift between client and server

Frontend allowed inputs the backend later rejected, creating bad UX.

Solution

Shared validation schema

Defined one validation schema reused by both client forms and Express middleware.
