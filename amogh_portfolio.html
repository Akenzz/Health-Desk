01 — Problem Domain

Bridging the gap between Connectivity and Care

Traditional telemedicine assumes perfect internet and immediate doctor availability. Health Desk addresses real-world constraints by introducing a resilient hybrid model.

📶

Connectivity Limits

Patients in low-bandwidth areas struggle with live video calls. We needed a store-and-forward solution that doesn't drop the patient when the connection drops.

⏱️

Asynchronous Care

Doctors aren't always online. Health Desk's MedReach feature allows patients to submit symptoms via audio/text for doctors to review and respond to later.

🌐

Language Barriers

Medical interfaces are often strictly English. Our AI bot dynamically detects Hinglish and Native scripts, translating intents automatically for inclusive access.

🏥

Fragmented Workflows

Consultations, medical records, and pharmacy prescriptions live in silos. We unified them under one role-based MVC system.

03 — System Architecture

Mapping the Ecosystem

Health Desk decouples the UI from core services and AI intelligence, allowing independent scaling and language-specific optimizations.

Next.js Client

Manages client-side routing, WebRTC media handling (Jitsi), and real-time sockets.

Express & Spring Boot

Express handles auth routing and file uploads; Spring Boot manages the heavy core business logic.

FastAPI Intelligence

A separate Python server exclusively for running LangChain, Pinecone retrievals, and LightGBM models.

JWT & Role-Based Access Flow

1. Client submits credentials/OTP to /healthdesk/auth.

2. Node.js validates via MongoDB and generates stateless JWT with role claims.

3. Next.js stores token and passes via Authorization: Bearer headers.

4. Express/Spring middleware decodes JWT and enforces route-specific RBAC (Patient vs Doctor).

04 — Intelligence Layer

The FastAPI AI Pipeline

We built a dedicated Python microservice to handle the heavy lifting for medical intelligence, separating ML processing from standard CRUD operations.

💬

Medical Bot (RAG)

A conversational assistant powered by Retrieval-Augmented Generation.

  • LangChain + Pinecone Vector Store
  • Groq LLaMA models for fast inference
  • Dynamic Hinglish & Native Script translation
  • Context-aware conversation history tracking
🧬

Disease Prediction

Machine learning models that suggest possible conditions based on symptoms.

  • Scikit-learn / LightGBM models
  • Joblib artifact loading
  • Maps raw symptom inputs to feature vectors
  • Returns top probable conditions with confidence
📝

MedReach Analysis

The brain behind our asynchronous consultation fallback system.

  • Audio transcription via AssemblyAI
  • Generates structured medical summaries
  • Evaluates severity before backend routing
  • Fallbacks to deterministic logic on API failure

09 — Overcoming Obstacles

Engineering Challenges

Problem

AI Bot Multilingual Context Loss

The Pinecone vector store was indexed in English. When users asked questions in Hindi or Hinglish, the RAG pipeline failed to retrieve relevant documents, causing hallucinations.

Solution

Pre-retrieval Translation Layer

Implemented a secondary lightweight Groq model (Llama-3.1-8b) specifically to detect language/script and translate to English *before* querying Pinecone. The system prompt then enforces output in the user's original script.

Problem

Handling MedReach File Uploads to Python

Routing multipart/form-data audio files directly from the Next.js client to the FastAPI server caused CORS and token-validation architecture leaks.

Solution

Express Gateway Proxying

Next.js sends the file to the Express backend (`/send/data/conversation`). Express validates the JWT, uses Multer for memory storage, and securely forwards the buffer to the internal AI service.
